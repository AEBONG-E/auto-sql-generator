## 1. 전체 사용자 여정 (User Journey)

### 1-A. 최상위 흐름

```
[앱 진입]
    │
    ▼
[프로젝트 목록 화면]  ──────────────────────────────────────────────────
    │ 프로젝트 없음                     │ 기존 프로젝트 선택
    ▼                                   ▼
[프로젝트 생성 모달]            [프로젝트 워크스페이스]
    │                                   │
    │ 생성 완료                         │ (파일 있음 / 없음 분기)
    ▼                                   │
[프로젝트 워크스페이스]  ←─────────────┘
    │
    ├─ 파일 없음 → [파일 업로드 존 (빈 상태)]
    │
    └─ 파일 있음 → [ERD / SQL 탭 화면]
                        │
                        ├─ ERD 탭: Draw.io 다이어그램
                        └─ SQL 탭: 자연어 → SSE 스트리밍
```

### 1-B. 세부 상태 정의

| 상태 ID | 조건 | 표시 내용 |
|---------|------|----------|
| `S0_PROJECT_EMPTY` | 프로젝트가 하나도 없음 | "첫 프로젝트를 만들어 시작하세요" 온보딩 화면 |
| `S1_PROJECT_LIST` | 프로젝트 1개 이상 존재 | 프로젝트 목록 카드 그리드 |
| `S2_PROJECT_SELECTED_NO_FILE` | 프로젝트 선택, 파일 없음 | 파일 드롭존 (업로드 유도) |
| `S3_UPLOADING` | 파일 업로드·파싱 중 | 프로그레스 인디케이터 |
| `S4_ERD_READY` | 파일 ≥ 1개, ERD 탭 활성 | Draw.io 다이어그램 + 사이드바 |
| `S5_SQL_READY` | 파일 ≥ 1개, SQL 탭 활성 | 자연어 입력 + SSE 출력 |
| `S_ERR_UPLOAD` | 업로드/파싱 실패 | 에러 토스트 + 재업로드 유도 |
| `S_ERR_SQL` | SQL 생성 실패 | 인라인 에러 메시지 |

### 3-B. Left Sidebar

**너비**: 260px (고정) | **섹션 간 구분**: 1px solid `--border`

#### 섹션 1 — 현재 프로젝트 컨텍스트

```
┌──────────────────────────────┐
│ 📁 my-service-db        [···]│  ← 프로젝트명 + 옵션 메뉴
│ 파일 3개 · 테이블 24개        │  ← 요약 메타
└──────────────────────────────┘
```

- `[···]` 클릭 → 컨텍스트 메뉴: "프로젝트 이름 변경 / 프로젝트 초기화 / 프로젝트 삭제"
- 프로젝트 초기화: 모든 파일 + 메타데이터 삭제 (확인 모달 필수)

#### 섹션 2 — 파일 목록

```
┌──────────────────────────────┐
│ 업로드된 파일  [+ 파일 추가]  │  ← 섹션 헤더 + 추가 버튼
├──────────────────────────────┤
│ 📄 schema_v1.xlsx            │
│    테이블 12개    [삭제 ×]   │
│ 📄 schema_v2.xlsx            │
│    테이블 12개    [삭제 ×]   │
└──────────────────────────────┘
```

- 파일 없을 때: "파일을 추가하면 메타데이터가 등록됩니다" (연한 회색 텍스트)
- `[× 삭제]` 클릭 → 확인 다이얼로그 (인라인, 모달 아님)
- `[+ 파일 추가]` → 파일 선택 → 업로드

#### 섹션 3 — 테이블 필터

```
┌──────────────────────────────┐

├──────────────────────────────┤
```

## 4. 주요 인터랙션 정의

### 4-A. 파일 업로드 진행 상태 인디케이터

3단계 상태 표시:

```
1. 파일 읽는 중...    ○ ──── ○ ──── ○
   [파일명.xlsx]     업로드  파싱   완료

2. 스키마 파싱 중...  ● ──── ○ ──── ○
   [파일명.xlsx]

3. 저장 완료          ● ──── ● ──── ●  (모두 초록색)
   [파일명.xlsx]      → 자동으로 ERD 뷰로 전환 (0.5s 딜레이)
```

- 인디케이터 위치: 메인 컨텐츠 중앙
- 현행 `progressZone`을 위 3단계 UI로 대체

---

### 4-B. 파일 삭제 확인 플로우

인라인 확인 (모달 없음):

```
삭제 전:
📄 schema_v1.xlsx    테이블 12개    [× 삭제]

클릭 후 → 해당 행이 확인 상태로 전환:
📄 schema_v1.xlsx    삭제할까요?  [확인]  [취소]
```

- 애니메이션: 0.2s fade 전환
- `[확인]` → `DELETE /api/v1/projects/{id}/files/{filename}` → 파일 목록 + ERD 갱신
- 마지막 파일 삭제 시 → `S2_PROJECT_SELECTED_NO_FILE` 상태로 복귀

---

### 4-C. SQL 생성 중 단계 인디케이터

```
생성 버튼 클릭 직후:
┌─────────────────────────────────────────────────┐
│  단계 1/2  테이블 분석 중...                     │
│  ████████░░░░░░░░░░░░░░░░░  (애니메이션 바)     │
└─────────────────────────────────────────────────┘

Step 1 완료, Step 2 시작:
┌─────────────────────────────────────────────────┐
│  단계 2/2  SQL 생성 중...                        │
│  ████████████████░░░░░░░░░  (바 더 채워짐)      │
│  분석된 테이블: users, orders, order_items       │
└─────────────────────────────────────────────────┘

SSE 스트리밍 시작 후:
인디케이터 사라지고 SQL 텍스트 스트리밍 시작
```

### 4-D. 에러 상태 UX

| 에러 종류 | 표시 위치 | 지속 시간 |
|----------|-----------|-----------|
| 파일 형식 오류 | 업로드 존 하단 인라인 | 3.5s 자동 소멸 |
| 파싱 실패 | 토스트 (우하단) | 3.5s + 수동 닫기 |
| 업로드 타임아웃 | 토스트 + 재업로드 CTA | 수동 닫기 |
| SQL 생성 실패 | SQL 출력 영역 인라인 | 수동 닫기 |
| 중복 테이블 경고 | 경고 토스트 (노란색) | 4s 자동 소멸 |

토스트 스타일:
- 위치: 화면 우하단, margin 20px
- 최대 너비: 320px
- 아이콘: ✓ (성공) / ⚠ (경고) / ✕ (에러)

## 8. Frontend 개발자를 위한 구현 우선순위

### P0 — 핵심 플로우

- 프로젝트 목록 화면 (`GET /api/v1/projects`)
- 프로젝트 생성 모달 (`POST /api/v1/projects`)
- 프로젝트 선택 → 워크스페이스 진입 (URL: `/?projectId=xxx`)
- 기존 파일 업로드·ERD·SQL 흐름을 `projectId` 파라미터 기반으로 전환

### P1 — 상태 품질

- 파일 업로드 3단계 인디케이터
- 파일 삭제 인라인 확인 UI
- SQL 생성 단계 인디케이터 (Step 1 완료 시 분석 테이블 목록 표시)

### P2 — 구조 정비

- 사이드바 3섹션 구조 (프로젝트 컨텍스트 / 파일목록 / 테이블 필터)
- 헤더 프로젝트 전환 드롭다운
- Context Bar 분리

### P3 — 접근성·반응형

- ARIA 레이블 적용
- 1024px 이하 사이드바 토글

> 현행 CSS 디자인 토큰(`--bg`, `--surface`, `--accent` 등)은 이미 AI 서비스 스타일에 근접한 수준이므로 전면 교체 없이 신규 컴포넌트에 동일 토큰 적용 권장.
